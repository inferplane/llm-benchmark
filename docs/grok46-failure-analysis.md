같은 모델을 호출한 다른 작업도 포함될 수 있고, 문서·요청 ID별 연결 정보가

서버 오류 수와 지연시간·첫 토큰 시간 지표는 제공되지 않아 확인할 수 없었습니다.

## 확인된 실행기 문제와 수정

1. **오류 정보 손실:** `str(exception)`만 저장하면 메시지가 없는 타임아웃
   예외가 빈 문자열이 됩니다. 예외 종류와 읽을 수 있는 설명을 남기고,
   가능한 HTTP 상태·실패 단계·요청 ID를 함께 기록합니다. 번역과 채점의
   오류 상세는 서로 다른 필드에 보관합니다.
2. **한 실행 안의 복구 정책 부재:** 일시적인 전송·서비스 오류를 분류하여
   제한된 지수 백오프와 지터로 재시도합니다. Grok 4.6은 처음 호출을 포함해
   최대 4회이며, 인증·잘못된 요청·콘텐츠 거절을 같은 방식으로 반복하지 않습니다.
   모든 시도는 JSONL에 남습니다.
3. **잘못된 완료 신호:** 실패가 남아도 CLI가 종료 코드 0으로 끝나던 동작을
   고칩니다. 요청된 작업이 남으면 실패 종료하고, 같은 실행을 다시 호출하면
   성공한 캐시는 유지한 채 미완료 키만 처리합니다. 빈 응답이나 완료되지 않은
   응답도 성공 캐시로 취급하지 않습니다.

모델 ID `xai.grok-4.6`, Mantle `us-west-2`, 추론 `low`, 온도 요청 0,
출력 상한 4,096토큰과 기존 120초 제한은 유지합니다. 변경된 재시도 설정은
실행 manifest와 리포트의 모델 설정에 기록합니다.

9월 13일의 원본 결과와 실패 시도를 보존하고, 실패한 55개 문서만 별도 복구

`completed`로 반환됐고, 동일한 두 평가 모델을 통한 채점도 55건 모두

새 재시도 코드나 시간 제한 변경이 복구의 원인이었다고 해석하지 않습니다.

원본의 성공 결과와 복구 결과를 `(model, id)`별로 합친 Grok 4.6의 최종 범위는

실패를 주입해 별도로 검증했습니다.

여러 날짜의 부분 실행을 합친 Grok 처리량은 제공하지 않습니다. 토큰 단가
비용과 품질은 집계할 수 있지만, 실패·재시도의 미기록 과금까지 포함한 청구서
총액이라는 의미는 아닙니다. 비교 시점과 실제 실행 조건은 각 source run의
manifest를 따라야 합니다.
