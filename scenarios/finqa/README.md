# FinQA 방식 금융 수치 추론

재무 문서의 본문과 표를 읽고 질문에 맞는 계산식을 생성하는 시나리오입니다.
번역 파이프라인과 별도로 실행하며, 모델 호출·재시도·성공 캐시는 기존
`bench.run`을 공유합니다. 모델과 추론 설정은 `config.toml`을 그대로 사용합니다.
Amazon Translate는 생성 모델이 아니므로 사용할 수 없습니다.

## 전체 모델 비교

`bench.finqa_compare`는 번역 통합 보고서의 모델 목록에서 생성 모델을 비교합니다.
각 모델의 소스 실행은 `<비교ID>-<모델명>`으로 저장해야 합니다. 예를 들면:

```bash
uv run python -m bench.finqa run --models nova-pro \
  --dataset data/finqa-dev.jsonl --run-id finqa-all-20260918-nova-pro
# 나머지 생성 모델도 같은 데이터 파일·프롬프트로 개별 실행한 뒤:
uv run python -m bench.finqa_compare --run-id finqa-all-20260918
uv run python -m bench.finqa_compare --selfcheck
```

2026-09-18 비교 대상은 API 24개, 자체 호스팅 4개입니다. Amazon Translate는
수치 질의응답을 지원하지 않아 제외 사유를 표시합니다. 필요한 모델 실행이
없으면 보고서 생성을 실패시키며, 일부 모델을 조용히 생략하지 않습니다.
데이터·프롬프트·출력 한도·호출 코드가 다른 소스도 섞지 않습니다.
자체 호스팅 모델은 해당 모델을 실제로 서빙한 상태에서 개별 실행해야 합니다.
이번 수집은 API 모델 최대 3개 병행, GPU 모델 순차 실행으로 진행했습니다.

전체 비교는 `finqa-execution-v2` 채점입니다. JSON 전체를 감싼 코드블록과
문자열 배열로 표현한 계산 단계만 모든 모델에 공통 정규화합니다.
이는 계산식의 숫자·연산·단위·참조를 바꾸지 않습니다. 설명문에서 JSON을
임의 추출하거나, 중첩 계산식·잘못된 참조·부호·100배 차이를 고치지 않습니다.
정규화 전 정답 수와 정규화된 응답 수를 함께 보존합니다.
기존 단일 모델 `evaluate`/`report`와 파일럿은 엄격한 원본 형식 평가이므로
전체 비교 점수와 직접 비교하지 마세요.

비용은 기존 `bench.report.aggregate_full`의 모델 전체 비용 계산을 재사용합니다.
정답 여부와 관계없이 정상 수신한 응답의 토큰을 포함하며,
실패·미응답이 있으면 문항당 비용 추정치를 제공하지 않습니다.
GPU의 비용은 관측한 요청 배치 시간에 대한 추정치이며 준비·다운로드·유휴 시간을
포함하지 않습니다. 여러 번의 GPU 실행이 섞이면 비용·처리량을 제공하지 않습니다.
단가 유효기간이 지난 Sonnet 5도 비용을 제공하지 않습니다.
설정 단가로 계산한 추정치이므로 전체 실험의 실제 AWS 청구액은 아닙니다.

전체 보고서는 모델별 정답·오답·계산식 오류·요청 실패·미응답, 형식 정규화,
추정 비용, 지연시간을 제공하며 공개 대시보드의 기본 실행으로 연결됩니다.
20문항과 원본 주석의 한계는 유지되므로 금융 업무 전반의 순위로 해석하지 않습니다.

## 실행

```bash
# 공식 dev 데이터에서 고정 seed로 20문항 준비. 모델 API 호출 없음.
uv run python -m bench.finqa prepare

# 명시한 모델만 호출. 이 단계에 모델 사용료가 발생합니다.
uv run python -m bench.finqa run \
  --models nova-lite --run-id finqa-nova-lite-pilot

# 계산식 실행·근거 ID 평가. LLM judge와 추가 API 비용 없음.
uv run python -m bench.finqa evaluate --run-id finqa-nova-lite-pilot
uv run python -m bench.finqa report --run-id finqa-nova-lite-pilot

# 정적 보고서 미리보기
python3 -m http.server 8000 -d docs
# /finqa-results/finqa-nova-lite-pilot.html 열기

# API 없는 자체 검증
uv run python -m bench.finqa selfcheck
```

`--models nova-lite,nova-pro`처럼 여러 모델을 지정할 수 있습니다.
`run --limit 5`는 선택할 전체 문항 수를 제한합니다.
`prepare --limit N`으로 표본을 늘릴 수 있지만 새 run-id를 사용해야 합니다.
동일 seed·원본에서는 기존 표본이 더 큰 표본의 앞부분으로 유지됩니다.
전체 평가를 명시적으로 원하면 `prepare --limit 883`을 사용합니다.

`prepare --source /path/to/dev.json`은 공식 원본 형식의 로컬 JSON도 받습니다.
이 경우 메타데이터에 로컬 경로와 실제 파일 해시를 기록하며, 해당 파일이
공식 커밋의 원본이라는 사실을 자동 검증하지는 않습니다.

## 데이터와 출처

- 공식 저장소: https://github.com/czyssrs/FinQA
- 논문: https://arxiv.org/abs/2109.00122
- 고정 커밋: `0f16e2867befa6840783e58be38c9efb9229d742`
- 원본: `dataset/dev.json`, 883문항
- 기본 표본: ID 정렬 후 seed 13으로 섞은 앞 20문항
- 원본 데이터의 영어 본문·표·질문을 사용합니다. 한국어 번역본이나 합성 문제가 아닙니다.
- 원본 SHA-256, 표본 해시, 출처 URL은 `data/finqa-dev.meta.json`에 기록합니다.
- 원본 저장소의 MIT 고지는 [LICENSE.FinQA](LICENSE.FinQA)에 보존합니다.

모델 입력은 본문·표·질문만으로 구성합니다. `qa.answer`, `qa.exe_ans`,
`qa.program`, `qa.gold_inds`는 평가용으로만 보관하고 입력에서 제외합니다.
정답 근거만 추려서 주는 방식이 아니라 해당 문서의 전체 제공 문맥을 사용합니다.

## 평가

주 지표는 **실행 정답률**입니다.

`실행 정답률 = 모델 계산식의 실행 결과가 qa.exe_ans와 같은 문항 수 / 선택한 전체 문항 수`

모델 출력은 `{"program": "...", "evidence": ["table_1"]}` 형식입니다.
허용된 사칙연산·거듭제곱·비교·표 집계만 최대 64단계 실행합니다.
Python `eval`/`exec`, 파일 접근, 네트워크, 임의 함수 호출은 허용하지 않습니다.
최종 수치만 소수점 다섯 자리에서 반올림한 뒤 공식 실행 정답과 정확히
비교합니다. 중간 계산은 반올림하지 않습니다. 비교 연산은 `yes`/`no`로 평가합니다.

부호나 100배 차이를 정답으로 보정하지 않습니다. 단위와 백분율 처리는
프롬프트에 명시되어 있습니다. 원본의 읽기용 정답과 실행 정답이 다른 사례,
비율과 백분율 수치가 일관되지 않은 사례가 있으므로 `exe_ans`를 기준으로
유지합니다. 별도 단위 정확도는 신뢰할 수 있는 단위 라벨이 없어 제공하지 않습니다.

초기 파일럿의 “백분율은 소수 비율로 출력” 지시는 일부 공식 정답의 단위와
충돌해 제거했습니다. 기존 실행은 당시 프롬프트와 응답을 그대로 보존하며
보고서에 경고를 표시합니다. 지시 수정만으로 원본 데이터의 단위 모호성이
해결되지는 않습니다. 모든 보고서는 출력 규약 확인용 파일럿으로 표시합니다.

요청 실패, 형식·계산 오류, 미응답은 정답이 아니며 모두 분모에 포함됩니다.
미응답과 실제 요청 실패를 분리하고 응답 커버리지도 제공합니다.
정상 응답이 틀렸다고 모델을 재호출하지 않으며, 통신 실패만 기존 재시도 정책을 따릅니다.
모델 계산식 실행불가는 표·본문 참조 사용, 인자 개수, JSON 형식 등의 원인별로
집계합니다. 정상 실행된 오답과 구분하며, 문항별 원본 응답·정답·오류 상세를
HTML 보고서에서 직접 확인할 수 있습니다.

근거 ID 완전일치율은 모델이 제시한 ID 집합과 공식 `gold_inds` 키 집합을 비교하는
보조 지표입니다. 중복 ID와 순서는 무시합니다. 다른 타당한 근거를 제시해도
불일치할 수 있고, 근거 ID가 맞는다고 설명이나 계산이 타당함을 보장하지 않습니다.
계산식 오류·미응답도 이 지표의 전체 문항 분모에 포함합니다.

이는 고정 dev 표본에 대한 zero-shot 전체 문서 평가입니다. 공식 학습·검색 설정,
공식 test 점수, 기호적 계산식 동치 정확도(program accuracy)와 동일하지 않습니다.
20문항은 기능 확인용 소표본이므로 모델 순위나 금융 업무 전반의 성능으로
일반화하지 않습니다. 공개 데이터가 모델 학습에 포함됐을 가능성도 있습니다.
추론 설정은 모델별 기존 설정을 유지하므로 동일 추론 예산을 보장하지 않습니다.

## 결과와 재현

```text
data/finqa-dev.jsonl
data/finqa-dev.meta.json
results/finqa/<run-id>/
  manifest.json       # 데이터·프롬프트·코드·모델 설정과 실행 이력
  dataset.jsonl       # 실행에서 선택한 데이터의 고정 스냅샷
  answers.jsonl       # append-only 모델 응답
  evaluations.jsonl   # append-only 결정적 평가
  report.json
docs/finqa-results/<run-id>.json
docs/finqa-results/<run-id>.html
```

응답·평가는 `(model, id)`별 마지막 행을 사용합니다. 실패한 마지막 응답이
이전 성공을 덮으면 이전 평가도 무효화됩니다. 데이터·프롬프트·모델 설정이나
호출 코드가 바뀐 상태에서 같은 run-id의 응답을 재사용하지 않습니다.
평가기는 응답과 평가 코드의 해시를 저장하며, 오래된 평가로 보고서를 만들면
`evaluate` 재실행을 요구합니다. 같은 run-id의 동시 실행은 파일 잠금으로 차단합니다.

번역 보고서와 결과 인덱스는 이 시나리오에 사용하지 않습니다.
단일 모델 파일럿 보고서에는 비용 지표가 없습니다. 응답별 토큰·지연시간은 원본 응답에 남으며,
이를 실패한 요청·재시도·유휴 GPU까지 포함한 실제 청구 비용으로 해석하지 않습니다.
