# FinQA 재검증 계획

작성일: 2026-09-19  
상태: 계획 확정 및 기존 결과 재현 완료. 새 평가 규약 구현·문항 감사·재측정은 미완료.

## 목표와 범위

GPT-5.5와 GPT-5.6 Terra의 차이를 사전에 가정하지 않고, 금융 계산 능력과
단위 표현·문법 준수·데이터 오류를 구분할 수 있는 평가를 만든다.
순위가 예상과 다르다는 이유로 실패로 판정하거나 규칙을 변경하지 않는다.

기존 28개 생성 모델을 유지한다. 번역 전용 Amazon Translate와 기존에
비활성화된 모델은 대상에 추가하지 않는다. 모델 ID, 추론 설정, 컨텍스트,
GPU 사양은 임의로 변경하지 않는다. 우선 새 표본도 모델당 20문항으로 제한한다.
새 20문항 결과 역시 일반적인 모델 우열을 확정하는 대규모 벤치마크로 부르지 않는다.

## 1. 기존 결과 보존 및 재현 — 완료

- 기존 560개 응답, 실행 설정, 데이터, 프롬프트와 공개 결과를 보존한다.
- 28개 모델의 원본으로 비교 JSON을 다시 구성하여 공개 JSON과 객체 전체가
  일치함을 확인했다. 모델당 20문항, 요청 실패·누락 0건이다.
- FinQA 실행기, 비교·출처 검증, 비용 계산의 기존 자체 검사를 모두 통과했다.
- 두 GPT 모델의 40개 계산 결과는 공식 실행기와 일치했다. GPT-5.5는
  정답 13건·100배 표현 차이 2건·기타 불일치 5건, Terra는 각각 4·9·7건이다.
- 이 검증은 구현의 재현성 확인이다. 정답 라벨이나 평가 설계가 타당하다는
  증거로 사용하지 않는다.

증거: `gpt55-terra-audit-20260919.md` 및 같은 이름의 JSON.

## 2. 기존 20문항 전수 감사 — 다음 작업

두 모델만이 아니라 기존 28개 모델의 결과를 동일한 분류 규칙으로 진단한다.
각 문항에 원문 근거, 질문 대상, 기준 시점, 분자·분모, 단위, 수작업 계산,
공식 정답과의 차이, 감사 판단 근거를 기록한다.

분류는 다음과 같이 분리한다.

| 축 | 기록할 내용 |
|---|---|
| 문항 품질 | 명확함 / 질문의 대상·방향·기간이 모호함 / 정답 주석 오류 / 근거 부족 |
| 응답 상태 | 정상 / 요청 실패 / 누락 / 미완료·잘림 |
| 출력 형식 | 정상 / JSON 문제 / 계산식 문법 문제 |
| 계산 결과 | 공식 값 일치 / 단위 표현 차이 / 숫자·연산·분모·방향 오류 / 판단 유보 |

하나의 응답에 여러 문제가 있으면 모두 기록한다. 특히 PNC처럼 원본 정답의
단위가 틀리고 모델도 다른 분모를 선택한 경우를 단위 차이만으로 분류하지 않는다.
100배·1,000배 근접 검사는 진단 후보 탐색에만 쓰고 자동 정답 처리하지 않는다.

통과 조건: 20문항 모두 근거가 작성되고, 판단이 갈리는 항목은 모호함으로
명시되어야 한다. 기존 출력에 맞춰 고친 정답률은 새 성능 결과로 발표하지 않는다.

## 3. 새 평가 규약과 검증용 문항 확정

### 서로 다른 점수의 이름을 구분

- **기존 FinQA 실행 일치율:** 원본 `qa.exe_ans`와 기존 규칙을 그대로 사용한
  과거 기록. 공식 리더보드와 다른 표본·프롬프트라는 점을 명시한다.
- **감사된 금융 QA 실행 정답률:** 정답 단위와 근거를 사전 검증한 새 규약의
  점수. 공식 FinQA 점수로 부르지 않는다.
- 요청 성공률, 형식 준수율, 잘림 비율을 별도로 표시한다. 주 정답률 분모에는
  모든 예정 문항을 포함하고, 정상 실행 문항만 골라 주 점수를 높이지 않는다.

### 단위 규약

응답은 계산식과 결과 단위를 함께 제출한다. 단위는 `ratio`, `percent`,
`percentage_point`, 금액·금액 배율, 개수 등 제한된 목록으로 정의한다.
각 문항의 허용 답변 단위와 기준 단위, 환산 규칙은 호출 전에 확정한다.

예를 들어 백분율 질문에서 `28.125 percent`와 `0.28125 ratio`는 동일한
기준 비율로 환산할 수 있다. 단위가 없는 28.125를 정답값과 비교한 뒤
임의로 100으로 나누지는 않는다. ratio를 명시적으로 요구한 질문에 percent로
답한 경우에는 숫자 의미의 일치와 요청 단위 준수 여부를 별도 기록한다.

계산식 실행, 선언 단위 환산, 최종 반올림 순서를 고정한다. 기존의 5자리
반올림을 사용하더라도 반드시 기준 단위로 환산한 뒤 적용한다.
허용 오차와 반올림 경계 규칙을 문서와 테스트에 동일하게 고정한다.
출력 단위가 누락되거나 의미가 불명확하면 추측하지 않고 분리 집계한다.

### 평가용 새 20문항

기존 20문항은 이미 모델 출력과 함께 검토했으므로 규약 개발·오류 진단용으로
한정한다. 원본의 고정 revision에서 기존 문항을 제외하고 새 후보를 고정 seed
`20260919`로 순서화한다. 선택 규칙·제외 이유·교체 순서를 모두 기록한다.

새 후보는 모델 호출 전에 본문·표·단위·정답을 감사한다. 모호한 문제는 모델별
결과를 보기 전에 제외하고 정해진 다음 후보로 교체한다. 출처 데이터의 단위와
분모가 잘못된 경우에는 후보를 제외하며, 모델에 유리한 라벨로 수선하지 않는다.
숫자·정답 계산은 독립된 방식으로 두 번 검산하고 의미 판단의 근거도 검토한다.
기존 평가에서 보지 않은 문항이라는 의미이며, 모델의 학습 데이터에 없었다는
보장은 하지 않는다.

통과 조건: 20문항의 근거·단위·정답에 미해결 문제가 없어야 한다.
데이터, 프롬프트, 평가기, 정답·단위 목록의 해시를 호출 전에 고정한다.
후보의 점수가 높거나 낮다는 이유로 문항을 교체하지 않는다.

## 4. 평가기와 요청 경로 검증

모델을 호출하기 전에 수작업 기대값으로 다음을 검증한다.

| 검증 사례 | 기대 결과 |
|---|---|
| 같은 비율을 소수·퍼센트로 선언 | 허용 단위 규약에 따라 동일 기준값 |
| 실제 값이 100배 틀리고 같은 단위를 선언 | 오답 |
| million/billion 변환 | 사전 정의된 차원·배율로만 환산 |
| 퍼센트 변화와 퍼센트포인트 차이 | 서로 다른 계산으로 구분 |
| 부호·분모·기간을 변경 | 단위 정상화로 구제하지 않음 |
| 반올림 경계와 작은 비율 | 기준 단위에서 한 번만 반올림 |
| JSON 오류·잘못된 참조·나눗셈 0 | 정해진 실패 분류, 분모에는 포함 |
| 요청 실패·미완료·재시도·중복 | 원본 보존과 명시된 집계 규칙 준수 |
| 정답·감사 메모가 들어 있는 데이터 | 모델 프롬프트에는 노출되지 않음 |

새 정규화 계층과 기존 DSL 실행기를 분리한다. 공식 DSL과의 비교는 계산
실행에 대한 검사로만 사용하고, 새 단위 규약 전체가 공식 평가와 같다고 주장하지 않는다.

송신 payload를 가로채는 오프라인 검사로 실제 모델 ID, 엔드포인트, 출력 상한,
temperature의 포함·생략, reasoning 설정의 포함·생략을 확인한다.
기존 manifest의 `temperature=0`만으로 실제 greedy 실행이라고 표시하지 않는다.

reasoning effort가 생략된 모델은 `provider default / effective value unknown`으로
기록한다. 제공자가 반환하지 않는 추론 설정이나 모델 revision은 추정하지 않는다.
동일 입력·출력 상한과 동일 추론량은 다른 조건임을 보고서에서 구분한다.
원본 응답의 종료 상태와, 제공되는 경우 reasoning 토큰·해결된 모델 ID도 보존한다.
비밀키나 인증 헤더는 기록하지 않는다.

통과 조건: 양성·음성 사례 모두 통과하고, 알려진 Major/Critical 결함이 없어야 한다.

## 5. 같은 규약으로 28개 모델 재측정

단계 2~4를 통과한 뒤 새 run ID로 28 × 20 = 560개 응답을 수집한다.
GPT-5.5와 Terra의 첫 실행으로 요청 경로·완료 상태를 먼저 확인할 수 있으나,
점수에 따라 규약을 조정하지 않는다. 규약이 바뀌면 해당 결과는 진단 실행으로
보존하고 같은 새 규약으로 전체를 다시 실행해야 한다.

기존 모델·추론 설정·컨텍스트·출력 상한4096·GPU 조건을 유지한다.
지원하지 않는 파라미터를 강제로 추가하거나 Terra만 추론량을 높이지 않는다.
누락·실패 때문에 모델이 표에서 사라지지 않도록 한다.
형식 오류나 낮은 점수를 이유로 성공 응답을 재요청해 좋은 답만 고르지 않는다.
통신 재시도는 기존 정책을 따르고 시도별 비용과 실패 이력을 남긴다.

호출 전에 설정 단가의 유효성과 예상 비용을 확인하고, 추정 불가 항목은 명시한다.
문항 수 확대·추론 설정 변경·반복 실험은 이 1회 계획에 포함하지 않는다.
GPU 자원은 기존 전용 범위에서만 사용하고 완료 후 정리한다.

통과 조건: 28개 모델 각각의 예정 문항, 최종 상태, 실행 설정이 모두 보고서에
남아야 한다. 요청 실패·누락이 있으면 결과를 완전한 측정으로 표시하지 않는다.

## 6. 결과 검증 및 공개

GPT-5.5와 Terra는 같은 문항에서의 정오답 차이와 원인을 직접 대조한다.
전체 28개 모델에도 같은 분류·분모·단위 규칙을 적용한다.
주 점수, 형식·단위 준수, 실패, 비용·지연시간을 분리한다.
비용·처리량은 기존 원칙대로 모델 전체 단위로만 계산한다.

20문항은 한 문항당 5%p다. 정답률에는 표본 불확실성을 함께 표시하고,
근소한 차이를 확정적 우열로 서술하지 않는다. 신뢰구간의 단순 중첩 여부만으로
모델 간 유의성을 판정하지 않는다. 여러 모델을 탐색적으로 비교한 결과임을 명시한다.

구 규약 기록과 새 규약 결과를 명확히 구분한다. 의미가 다른 점수를 한 순위에
혼합하지 않는다. 공개 JSON 재생성, 문항별 원본 대조, 비용 검사, 화면 검증을
완료한다. 코드 변경 PR은 최신 HEAD의 AI 리뷰와 필수 검사를 통과한 뒤 머지한다.

최종 산출물은 문항 감사표, 고정 평가 규약, 재현 가능한 테스트, 새 실행 manifest,
28개 모델 원본·문항별 판정, 비교 화면, 비용·표본·추론 설정의 한계 설명이다.
